# HBT 手动回归测试清单

> 适用：`feature/league-tool-basic`（WPF 联赛工具，.NET Framework 4.7.2）
> 更新：2026-11-10
> 前身是一份 .NET 8 + Blazor 骨架时代的测试计划，已随架构切换整体重写

## 前置条件

1. Windows + 炉石传说正在运行（BGSpy 要读游戏内存，没开游戏只能验证「未连接」分支）
2. `dotnet build -c Release` 通过（0 错误）
3. 服务端可达：
   - Debug 版：`BGTRACKER_CONFIG` / `shared_config.json` / `config.json` 指向本地 `mock_server.py`
   - Release 版：内置正式服地址，直接联调线上
4. 报名/成组的完整链路需要服务端或 mock 支持 8 人；单人只能测到「排队中」

## 1. 启动与玩家信息

| 步骤 | 预期 |
|------|------|
| 未开炉石就启动 HBT | 窗口淡入，标题 `HBT - 联赛工具 v0.7.0`；状态「○ 检测中...」；日志出现「BGSpy 已断开」 |
| 此时点「🔄 刷新」验证码 | 拒绝并提示「刷新验证码失败：炉石未运行」，不 crash |
| 打开炉石并登录 | 状态变「● 已连接」，显示 `名字#1234` + 区域徽章 + MMR |
| 验证码出现后点「📋 复制」 | 剪贴板内容与显示的验证码一致 |
| 点「🔄 刷新」 | 拿到新验证码（服务端约 5 分钟轮换），日志有「验证码已刷新」 |

## 2. 联赛对局主流程

| 步骤 | 预期 |
|------|------|
| 进入酒馆战棋大厅并开一局 | 日志「获取大厅玩家信息...」「英雄: xxx (BGXX_xxx)」；UI 显示英雄 |
| check-league 返回联赛局 | 侧栏/主区进入对局态，不卡在「联赛检查中」 |
| check-league 返回非联赛局 | 跳过 update-placement，仍记录 MMR 变动与本地战绩 |
| 打完一局 | 显示名次而非「结算中...」；MMR 变动 +最近战绩刷新 |
| 中途异常离场（场景 4→15 未走到结算） | 日志「兜底结束」+「兜底已上报排名 N（timeout，不计分）」 |

## 3. 报名参赛

| 步骤 | 预期 |
|------|------|
| 未读到战网 ID 时点「参赛」 | 提示「请先启动炉石并读到战网 ID」，不发请求 |
| 正常点「参赛」 | 右侧栏展开，「排队中」，按钮变「退出排队」，出现排队进度 n/8 |
| 排队人数变化 | `queue_count` 事件刷新进度条与 n/8，不刷屏日志（Release） |
| 成组（8/8） | 「组队完成」，进度条隐藏，主面板显示「组队完成 / 请准备进入游戏」 |
| 同桌名单出现 | 显示 8 人，右上角 `8 / 8`；每行「⧉」可复制，点击后按钮变绿 ✓ 约 1.2s 复原 |
| 玩家陆续进房 | 已进房的名字变绿（加粗），每 2 秒轮询一次 |
| 正式开局（场景 15→4） | 日志「场景 15→4，战棋开局，停止进房检测」，轮询停止 |
| 对局结束 | 进入「请确认名次」，主按钮「确定」、副按钮「有异议」 |
| 点「确定」 | 提示「已确认名次 / 第 N 名无误」，按钮变「返回」 |
| 点「有异议」 | 提示「已提交异议，等待处理」 |
| 关闭 HBT | 自动退排（日志「退出 HBT，自动退出排队…」），服务端队列不残留 |
| 断网约 30 秒 | 日志「匹配事件流断开，自动重连 (n/3)」，恢复后状态自愈 |
| 断网超过重连上限 | 自动退排并回「未报名」 |

> 排查：连点主按钮不会重复发请求（入口统一 `IsEnabled` 保护）。

## 4. 其他

| 场景 | 预期 |
|------|------|
| 关闭窗口 | 渐隐后正常退出；不残留黑色矩形；单实例锁释放（可立即重启） |
| 卡牌库（BGDB）有新版 | 启动时提示更新，下载后等待炉石退出再替换，不出现「已在运行」误判 |
| 验证码过期后重开炉石 | 点刷新会先补拉玩家信息再 initialize，不再报「玩家信息尚未就绪」 |

## 5. 已知限制

- **8 人成组**：必须服务端或 mock 配合，单人无法自测
- **BGSpy 依赖真实炉石内存**：无法在 CI / 无头环境跑
- **战斗模拟 / 覆盖层 / 卡牌浏览器**：basic 分支已移除，不存在相关 UI，不要按旧文档去找
- **Debug 与 Release 差异**：Debug 有日志栏、可改 `apiBaseUrl`；Release 隐藏日志栏、地址内置且不读外部配置，事件原始 JSON 只在 Debug 记录

## 6. 出问题时看哪里

| 现象 | 排查 |
|------|------|
| 程序崩溃 | exe 同目录 `HearthstoneBattlegroundTracker_crash.log` |
| 行为异常 | exe 同目录 `HBT_debug.log`（Debug/Release 都会写） |
| 服务端 4xx/5xx | 日志里的 `[API] → / ←` 行，含完整请求体与响应体 |
| BGSpy 读不到数据 | 日志 `[BGSpy] ...`；确认炉石是 64 位且以管理员/同权限运行 |
