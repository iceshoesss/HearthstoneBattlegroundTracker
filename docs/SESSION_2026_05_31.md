# Session 总结 - 2026-05-31

## 完成的工作

### 1. BGSpy 功能修复与新增

**MMR 读取修复**：
- 通过 `HearthstoneJobs.s_dependencyBuilder` → ServiceLocator → NetCache 路径读取 MMR
- 字段名用 `<ServiceTypeName>k__BackingField` / `<Service>k__BackingField`（backing field 语法）
- 用 `TryGetField` 安全读取字段，避免 UnitySpy 抛异常
- `GetCollectionSize()` 兼容 UnitySpy `size()` 和 .NET `Array.Length`

**RatingChange 读取**：
- 路径：`GameState.s_instance.m_gameEntity.<RatingChangeData>k__BackingField`
- 字段名是 backing field 语法，直接访问 property 会抛异常
- 游戏结束后轮询获取（HDT 方案：5 次 × 500ms）

**场面读取**：
- 改用 `ZoneMgr.s_instance.m_zones._items` → `m_mousedOverSlot` 识别 ZonePlay
- `GetPlayerBoardMinions` / `GetOpponentBoardState` 都用 ZoneMgr 路径
- 对手场面新增 Attack/Health/Golden 字段

**其他**：
- `IsGameOver()` — `GameState.s_instance.m_gameOver`
- `GetBaconRatingChangeData()` — 游戏结束后分数变化
- 添加诊断方法：`DiagnoseServiceLocator`、`DiagnoseRatingChangeData`、`DiagnoseZoneMgr`

### 2. HBT 核心功能

**MMR 管理**：
- `_lastKnownMmr` 字段：不随 `_currentGame` 重置，确保每局起始 MMR 正确
- `TryReadMmr()` 统一 MMR 读取逻辑，同步更新 UI + 保存到 `games.json`
- `GameRecord.Rating` 在 `PollRatingChange()` 之前保存，确保是游戏开始时的 MMR
- 今日起始 MMR 存在 `games.json` 中（`{"type":"daily_mmr","date":"...","mmr":...}`），同一天不重复写入

**GamePhase 状态机**：
- `Idle → PreLobby → Lobby → Active → PostGame`
- BGSpy 启动检测替代日志扫描：`GetSceneMode()` 检测场景 4（游戏中）
- 场景读取失败时重试 5 次，每次间隔 2 秒

**check-league 流程**：
- `HandleCheckLeague`：读种族 → 读大厅信息 → 读 MMR → 调 API
- 大厅信息重试 3 次（500ms 间隔）
- `ReconnectEvent` 时如果已有大厅信息，跳过重复获取
- `isLeague: false` 时设为 Active 阶段，显示"对局进行中"

**HandleGameEnd 流程**：
- `PollRatingChange()` → 保存起始 MMR → `update-placement`（仅联赛）→ `GameStore.Save` → `ReportGameStats`
- 非联赛对局跳过 `update-placement`，保留 `report-game-stats` 和 `GameStore.Save`
- RatingChange 获取后更新 UI MMR

**report-game-stats API**：
- 端点：`POST /api/plugin/report-game-stats`
- 请求体：`gameUuid`、`playerId`、`accountIdLo`、`rating`、`boardState`、`ratingChange`
- `boardState` 用 `List<object>` 序列化（不是 `List<Dictionary>`）
